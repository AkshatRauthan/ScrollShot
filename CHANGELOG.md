# Changelog

All notable changes to this project are documented here. Format loosely follows [Keep a Changelog](https://keepachangelog.com/).

## [Unreleased]

### Added
- **Windows capture backend** (`internal/capture/windows.go`) — raw Win32 syscalls (GDI + `PrintWindow` with `PW_RENDERFULLCONTENT`), zero external dependencies. Handles DPI-aware coordinate scaling. Verified via cross-compilation for `windows/amd64` and `windows/arm64`; not yet runtime-tested on real Windows hardware.
- **X11 capture backend** (`internal/capture/x11.go`) — pure-Go X11 protocol client (`jezek/xgb`/`xgbutil`), no cgo/Xlib headers required. Finds the active window via EWMH (`_NET_ACTIVE_WINDOW`), captures via a real `GetImage` protocol request. Deliberately gated to `XDG_SESSION_TYPE=x11` only — does not attempt capture through XWayland, since that isn't reliable for native Wayland clients.
- **D-Bus portal capture backend** (`internal/capture/portal.go`) — talks directly to `org.freedesktop.portal.Screenshot`, removing the dependency on the `gnome-screenshot` binary and extending native support to any portal-compliant desktop (KDE included), not just GNOME. Captures full screen rather than a specific window, since the standard portal API has no window-specific concept.
- **Static-UI detection** (`stitch.DetectStaticEdges`) — scans all frames in a session at once (not just consecutive pairs) for rows that stay pixel-identical at the same position in every frame, and crops them before matching or pasting. Fixes sticky navs and fixed status bars getting duplicated in the output, or falsely treated as scroll overlap.
- `SCROLLSHOT_BACKEND` environment variable to force a specific capture backend, for testing or when the auto-selected default isn't the one you want.
- Dimension-mismatch validation in `stitch.Stitch` — frames of different widths now produce a clear, actionable error instead of being silently cropped to a common width and compared misaligned.

### Fixed
- **Dimension mismatch producing garbage output.** A capture-backend switch or window resize mid-session used to silently crop mismatched frames to a common width before comparing them, producing corrupted stitched output with no warning. Now a hard error, with frames preserved for inspection.
- **False full-height matches on backgrounds dominating a frame (98%+ of pixels).** The match-scoring metric originally computed agreement over *all* sampled pixels; on content where a uniform background dominates (a dark code editor, a large flat-color page section), background-vs-background trivially "matches" at almost any offset, making genuinely different scroll positions indistinguishable from the correct one. Fixed by excluding near-background pixels from the score, judging only distinctive content.
- **False matches on low-entropy, repetitive content** (e.g. a dark-theme code editor with sparse syntax-highlighted text). A single-pass sparse-sampling search could lock onto a coincidentally-similar wrong offset. Fixed with a two-pass search: cheap sparse scan across every offset to shortlist candidates, then dense full-column re-verification on the top candidate and its best distant rival before deciding.
- **Genuine matches rejected due to anti-aliasing/font-rendering noise.** Two independent screenshots of the same logical text content are never byte-identical — sub-pixel rendering varies between captures. The original tolerance was calibrated on clean synthetic data and was too strict for this, causing real matches to score 83–88% and be rejected. Recalibrated against a test built to reproduce the actual observed scores.
- **Sticky nav/status bar detection itself falling for the same background-domination bug it was meant to help fix.** `DetectStaticEdges` initially had no exclusion logic at all, then an early fix excluded a row's *entire* judgment if it looked "background-colored" — which incorrectly excluded genuinely solid-colored fixed UI (a plain-colored nav bar) from being recognized as static at all. Fixed with a fallback: judge on distinctive (non-background) content when there's enough to judge on, fall back to judging the whole row only when it's genuinely uniform.
- **Static-edge detection using coarse, sparse column sampling** and missing sparse real content (scattered syntax-highlighted text) in certain rows purely by sampling bad luck, wrongly classifying them as uniform/static. Static-edge detection only ever checks a small number of candidate rows once each (unlike the overlap search, which runs per-offset), so it can afford full-width scanning instead — switched to that.
- **Near-perfect matches (99–100% confidence) rejected by the margin/confidence-ratio check** on structurally repetitive real content (source code, with many similarly-shaped lines producing a distant rival that also scores deceptively high). Added a high-confidence override so a match scoring above a calibrated threshold bypasses the margin requirement — the threshold was set by measuring a real false-positive's score under adversarial conditions (repetitive content + rendering noise) and placing the bar with margin above it, not guessed.
- Stale, never-finished capture sessions (e.g. from an aborted run) auto-clear on the next `capture` instead of silently mixing old and new frames — no separate `start` command needed.

### Changed
- Project restructured from a single `main.go` into `cmd/scrollshot` (thin CLI layer) plus `internal/{capture,session,stitch,edit,export,autoscroll}` packages, each with one clear responsibility. `capture`, `session`, and `stitch` are fully implemented; `edit`, `export`, and `autoscroll` exist as locked-in interfaces with `ErrNotImplemented` stubs, ready to be filled in without further restructuring.
- Overlap-matching tolerance and static-edge-detection tolerance decoupled into separate constants (`pointTolerance` vs `staticEdgeTolerance`) after discovering that loosening one to fix a real-world matching issue was inadvertently loosening the other, causing static-region false positives.
- The cap on how much of a frame's edge can be classified as static UI (`maxStaticFraction`) tightened from 30% to 12%, based on the observation that real fixed UI (nav bars, status bars) rarely exceeds ~10% of a window's height — reducing over-cropping in edge cases like fully-identical consecutive frames.

## v0.1.0 — Initial project structure

- Initial GNOME-Wayland-only version: `gnome-screenshot`-based capture, sparse-sampling overlap matching, basic session management (`capture`/`finish` commands, stale-session auto-clear).
- Established the reason for the project's existence: `grim`/`slurp`-based tools fail on GNOME/Mutter with `compositor doesn't support zwlr_layer_shell_v1`, since Mutter doesn't implement the Wayland protocol they depend on.
